# 회고

## 이번 캡스톤에서 한 것

머니로그(가계부 웹 서비스)를 요구사항 정의 → ERD/API 설계 → 백엔드 CRUD → JWT 인증/인가 → 프론트 2종 → Docker/EC2 배포까지 기본 트랙 순서대로 진행했다. 도전 과제(예산, 통계 시각화, 검색, Jenkins/K8s 등)는 이번 범위에서 제외했다.

- 요구사항 정의서, ERD, API 명세서 작성
- User/Category/Transaction 엔티티 + JPA Repository
- 카테고리 CRUD, 거래내역 CRUD(월별 필터+페이징)
- Spring Security + JWT 로그인, 본인 데이터 인가(다른 사용자 데이터는 404로 차단)
- 월별 통계(총수입/총지출/잔액/카테고리별 지출)
- 로그인/거래목록+등록 화면 2종 (HTML/CSS/JS, fetch + localStorage)
- Dockerfile + docker-compose(app + MySQL)
- AWS EC2 배포, 실제 접속 URL로 회원가입~거래등록까지 동작 확인

## 배운 점

- 공통 응답 형식({success, message, data})으로 통일하니 프론트에서 성공/실패 처리가 단순해졌다.
- 본인 데이터 인가는 결국 모든 조회 쿼리에 `user_id` 조건을 빠짐없이 거는 것이 핵심이었다. Repository 메서드 이름에 `AndUserId`를 붙이는 습관을 들이니 실수를 줄일 수 있었다.
- JWT는 로그인 시 토큰만 발급하면 끝이 아니라, 필터에서 매 요청마다 토큰을 검증하고 인증 객체를 채워 넣어야 컨트롤러에서 로그인 사용자 정보를 쓸 수 있다는 걸 직접 구현하면서 이해했다.

## 어려웠던 점

- EC2 배포 과정에서 SSH 접속이 갑자기 안 되는 문제를 겪었다. 재부팅까지 해봤지만 소용없었고, 결국 원인은 서버 문제가 아니라 **테더링 환경에서 실제 발신 IP와 확인용 IP가 다르게 잡히는 것**이었다. 서버의 SSH 로그(`journalctl -u sshd`)에서 실제 접속 IP를 확인하고 나서야 원인을 알 수 있었다.
- Docker Compose로 이미지를 빌드할 때 `buildx` 플러그인이 없어서 빌드가 중간에 멈췄다. EC2 서버에 필요한 도구를 다 갖췄다고 생각했는데 실제로 빌드해보니 빠진 게 있었다 — 로컬에서 되던 게 서버에서 안 될 수 있다는 걸 배웠다.
- t3.micro(메모리 1GB) 위에서 Gradle 빌드가 오래 걸릴까 걱정했는데, 생각보다는 잘 돌아갔다.

## 다음에 개선하고 싶은 점

- GitHub Actions로 빌드까지는 자동화했지만, EC2 자동 배포까지는 연결하지 못했다. 다음엔 Actions에서 SSH로 배포까지 이어보고 싶다.
- 목록 필터(카테고리/타입)는 API 명세엔 넣었지만 화면에는 아직 못 붙였다. 여유가 생기면 추가하고 싶다.
- 도전 과제 중에서는 월 예산 설정 기능을 가장 해보고 싶다. 구조상 Budget 엔티티만 추가하면 될 것 같다.
