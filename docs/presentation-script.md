# 발표 스크립트 (3~4분)

실제로 말할 문장 그대로 적어둔 것. 외우기보다 흐름만 기억하고, 첫 문장과 마지막 문장만 외워두면 된다.

---

## 1. 문제 — 왜 만들었나 (약 30초)

> 안녕하세요, 개인 가계부 서비스 **머니로그**를 소개하겠습니다.
>
> 지금까지 자바 문법부터 스프링, 시큐리티, 프론트 연동, 도커랑 배포까지 따로따로 배웠는데요.
> 각각은 알겠는데 "그럼 처음부터 끝까지 서비스 하나를 혼자 만들어봐라" 하면 막막하더라고요.
> 그래서 배운 걸 전부 한 프로젝트에 넣어보려고 가계부를 골랐습니다.
>
> 가계부는 도메인이 단순해서 기능에 헷갈릴 일이 없고, 대신 **"내 데이터는 나만 봐야 한다"**는
> 인가 문제가 자연스럽게 들어있어서 연습하기 좋았습니다.

---

## 2. 기능 — 무엇을 할 수 있나 (약 40초)

> 기능은 크게 네 가지입니다.
>
> 첫째, **회원가입과 로그인**입니다. 비밀번호는 BCrypt로 암호화해서 저장하고, 로그인하면 JWT 토큰을 발급합니다.
>
> 둘째, **거래내역 등록, 조회, 수정, 삭제**입니다. 수입인지 지출인지, 얼마인지, 어떤 카테고리인지 기록합니다.
>
> 셋째, **카테고리 관리**입니다. 회원가입하면 식비, 교통, 주거, 문화, 급여, 용돈 이렇게 여섯 개가 자동으로 생기고, 직접 추가하거나 지울 수도 있습니다.
>
> 넷째, **월별 통계**입니다. 이번 달 총수입, 총지출, 잔액이랑 카테고리별로 얼마 썼는지 보여줍니다.
>
> 그리고 이 모든 조회는 **로그인한 사람 기준으로만** 나갑니다. 이게 이 프로젝트에서 제일 신경 쓴 부분입니다.

---

## 3. 시연 — 실제로 보여주기 (약 90초)

**미리 준비**: 브라우저에 로그인 화면 띄워두기. 로그아웃 상태로 시작.

시연용 계정 두 개
- `hong@moneylog.com` / `pass1234` — 거래내역 5건 들어있음
- `kim@moneylog.com` / `pass1234` — 비어있음 (인가 보여줄 때 사용)

> 실제로 배포된 화면으로 보여드리겠습니다.

**① 로그인** (약 20초)
- 이메일 `hong@moneylog.com` / 비밀번호 `pass1234` 입력 → 로그인 클릭

> 로그인하면 서버가 토큰을 주고, 브라우저는 그걸 저장해뒀다가 앞으로 모든 요청에 같이 보냅니다.

**② 목록과 통계 확인** (약 20초)

> 이번 달 거래내역이 나오고, 위쪽에 수입 250만원, 지출 52만 2천원, 잔액 197만 8천원이 보입니다.
> 이 잔액은 프론트에서 계산한 게 아니라 서버가 DB에서 집계해서 내려준 값입니다.

**③ 거래 등록** (약 30초)
- 구분: 지출 / 카테고리: 식비 / 금액: 9000 / 설명: 커피 입력 → 등록

> 등록하면 목록에 바로 추가되고, 위쪽 지출이랑 잔액도 같이 바뀝니다.

**④ 인가 보여주기** (약 20초, 여기가 포인트)
- 로그아웃 → `kim@moneylog.com` / `pass1234` 로 다시 로그인

> 이번엔 다른 사람 계정으로 로그인해보겠습니다.
> 같은 서버, 같은 화면인데 **거래내역이 하나도 안 보이고 통계도 전부 0원**입니다.
> 방금 전 계정이 등록한 데이터가 분명히 DB에 있는데도요.
>
> 조회 쿼리에 로그인한 사용자 조건을 같이 걸어놔서, 남의 데이터는 애초에 결과에 섞이지 않습니다.

## 4. 기술적 도전 — 가장 어려웠던 것 (약 60초)

> 가장 오래 붙잡았던 문제를 하나 말씀드리겠습니다.
>
> 어느 순간부터 **API를 부르면 403이 뜨는데, 응답 본문이 완전히 비어있는** 현상이 생겼습니다.
> 403이니까 당연히 권한 문제인 줄 알고, 시큐리티 설정에서 permitAll 경로를 이리저리 바꿔봤는데 전혀 해결이 안 됐습니다.
>
> 그래서 서버 로그를 직접 열어봤더니, 진짜 원인은 권한이 아니라 **전혀 다른 예외**였습니다.
> 처리 안 된 예외가 나면 스프링이 그 요청을 `/error` 라는 경로로 다시 보내는데,
> 제 설정에서는 "인증된 사용자만 접근 가능"에 `/error`까지 포함돼 있었습니다.
> 그러니까 에러 페이지 자체가 막혀서, **진짜 에러 내용 대신 403만 보였던 겁니다.**
>
> `/error`를 열어주고 나니 원래 에러가 그대로 보였고, 두 가지를 고칠 수 있었습니다.
> 하나는 Swagger 라이브러리 버전이 스프링 부트랑 안 맞았던 것, 다른 하나는 거래가 남아있는 카테고리를 지우려다 DB 제약에 걸린 것이었습니다.
>
> 여기서 배운 건, **에러 코드가 항상 진짜 원인을 알려주지는 않는다**는 겁니다. 로그를 봐야 합니다.

## 5. 회고 — 배운 것과 다음 계획 (약 30초)

> 마지막으로 회고입니다.
>
> **계속 하고 싶은 건**, 기능 하나 만들 때마다 서버를 띄워서 직접 호출해보고 넘어간 겁니다.
> 덕분에 "다 짰는데 안 돌아가는" 상황 없이 끝까지 갈 수 있었습니다.
>
> **다음에 고칠 건**, 로그인이랑 인증 구조를 먼저 잡고 기능을 얹는 순서로 하는 겁니다.
> 이번엔 기능부터 만들고 나중에 로그인을 끼워 넣어서, 컨트롤러를 전부 다시 고쳐야 했습니다.
>
> 배포 주소는 화면에 있는 그대로고, **지금 바로 접속해서 직접 써보실 수 있습니다.**
> 이상입니다. 감사합니다.

## 발표 팁

- 첫 문장("안녕하세요, 개인 가계부 서비스 머니로그를 소개하겠습니다")과 마지막 문장만 외워두면 중간은 훨씬 편해진다.
- 코드는 화면에 띄우지 않는다. 4번에서 말로만 설명해도 충분하다.
- 시연이 라이브로 실패할까 걱정되면 미리 화면 녹화(GIF)를 준비해둔다. Windows는 ScreenToGif 같은 무료 도구를 쓰면 된다.
- 시간이 모자라면 3번 시연의 ④번(인가 보여주기)만 살리고 나머지를 줄인다. 이 프로젝트의 핵심이라서.

## 예상 질문 대비

**Q. 인가는 어떻게 구현했나요?**
> 모든 조회 쿼리에 로그인한 사용자 id 조건을 같이 걸었습니다. 예를 들어 거래 하나를 찾을 때도 id만 보는 게 아니라 `findByIdAndUserId`처럼 사용자까지 같이 조건에 넣었습니다. 그래서 남의 데이터는 조회 결과 자체에 안 나오고, 404로 응답됩니다.

**Q. JWT는 어떻게 동작하나요?**
> 로그인에 성공하면 사용자 id를 담은 토큰을 만들어서 내려줍니다. 그 다음부터 요청이 오면 필터에서 토큰을 검사하고, 유효하면 그 사용자를 인증 정보에 넣어둡니다. 그래야 컨트롤러에서 "지금 로그인한 사람"을 알 수 있습니다.

**Q. 배포는 어떻게 했나요?**
> 앱을 도커 이미지로 만들고, docker-compose로 앱이랑 MySQL을 같이 띄웠습니다. 이걸 AWS EC2에 올렸고, GitHub에 푸시하면 GitHub Actions가 빌드를 확인해줍니다. 비밀번호나 토큰 키 같은 건 저장소에 올리지 않고 서버의 .env 파일로 따로 관리합니다.

**Q. 못 만든 건 뭔가요?**
> 목록을 카테고리나 타입으로 거르는 필터를 API 명세에는 넣었는데 구현을 못 했습니다. 예산 설정 기능도 도전 과제라 이번엔 제외했습니다.
